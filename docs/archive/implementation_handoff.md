## 要实现的内容

1. **三种模式全保留**：Mode 1 RViz 目标、Mode 2 参数航点、Mode 3 参考路线。记录原有高度语义及切换方法；原高度约束保留，不开发自由三维规划。
2. **运动方向与机身朝向分开**：从 odom 四元数获取有效 yaw，检查有限值/姿态有效性；跟踪使用实际 yaw 做世界系与机体系速度转换，支持保持车头横移、反向以及旋转中平移。取消全向模式下“先对齐轨迹 yaw 才走”的门槛，并保持 FSM/执行时间逻辑一致。
3. **碰撞模型配套修改**：审计 plan_env/grid_map、bspline_optimizer、FSM 检查与相关朝向推导。当前 yaw 只代表现在，不能无依据铺到未来整条轨迹。首版建议全朝向保守包络；外形、旋转中心、高度和余量参数化。规划代价、最终碰撞检查和 RViz 显示使用一致语义。精细朝向模型可后续再做。
4. **PCD 闭环仿真**：尽量复用现有 PCD 发布、局部观测渲染及运动模拟组件；新增/修改部分保持最小。跟踪器输出速度，模拟器积分更新姿态并反馈 odom；不得用 open_loop_controller 直接复制样条位置作为闭环验收。
5. **可用 RViz 入口**：提供实际可运行的 launch 和 RViz 配置，支持 PCD 路径、模式、初始姿态、尺寸与旋转策略参数。显示完整地图、局部观测/占据、机器人外形、朝向、碰撞包络、规划轨迹、执行轨迹和目标。Mode 1 配好 2D Goal Pose topic，不要求 Nav2 面板。
6. **基础保护**：无效/陈旧 odom、非法轨迹、取消、模拟器命令断流时停止；清除旧任务，不能重启后恢复旧速度。使用统一时钟，记录是否 use_sim_time；若启用必须有 /clock 来源。
7. **可复现实验与文档**：按 S0–S3 逐项记录，不用“编译成功”或一张截图替代运动/碰撞结果。

必要修改可以涉及 SCAN 局部碰撞、姿态、控制、FSM 时序、launch、仿真及相关测试。优先复用现有包，允许实现时调整旧文档建议的包名，但要说明理由与实际入口。

## 本阶段不要做

- 不接真实 UART，不发布实车 /cmd_vel；所有模拟输出隔离到仿真命名空间，防止同一 ROS 环境误接实车。
- 不修改 RM 的 LIO、registration、TF、Nav2 参数、串口协议或 MCU 小陀螺。
- 不迁移竞赛 BT、不删除 Nav2、不引入新的完整地形/拓扑全局规划器。
- 不因全向适配广泛重写 B-spline 数学或无关算法；不悄悄删除原有模式。
- 不把模拟旋转等同于固件策略，不把简化高度运动等同于真实爬坡验证。

## 输入仍需确认

- 用户 PCD 的路径、单位、坐标方向、可用初始位置及目标区域。
- 实际机器人长/宽/高、参考点/旋转中心、雷达位置与朝向；建议的安全余量。
- 仿真速度/加速度、旋转速度、跟踪误差与停止时限。

缺用户 PCD 时可用小型合成测试地图和显式示例尺寸开发；必须标记“示例，非实车参数”。PCD 不存在或参数无效应报错，不能悄悄换成演示地图并宣称指定地图通过。不要凭空指定实车安全阈值。

## 最低验收与审查材料

- 改动基线、工作目录/分支、修改文件与用途；提供 git diff 或补丁，不仅口头总结。
- 从干净终端起的依赖/构建/source/启动/停止步骤；不要依赖无法说明的旧 install。
- 每个模式的启动命令、输入方法与结果；PCD 路径/校验值、参数快照与 RViz 配置。
- 固定 yaw 横移、边转边走、障碍绕行、不可通过窄处、取消/数据断流的自动测试或可重放日志。
- 世界/机身速度转换样例（含 90° yaw）、碰撞包络独立几何检查、轨迹切换/执行时间测试。
- XY 跟踪误差、障碍间距、速度限幅与停止时间；注明阈值、通过/失败/未测，保留失败记录。
- 带高度路线所用模拟高度规则及局限；真实爬坡、摩擦/打滑、实车协议均标未验证。
- 若环境无法显示 GUI：可先交付无界面结果与可启动配置，但明确“RViz 交互未验证”，不能宣称验收完成。
