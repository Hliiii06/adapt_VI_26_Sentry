## 第五轮：Codex 复审修正 + 受控洞口场景

按 Codex 复审清单收敛，全部有实测证据：

- **高度语义统一**：局部轨迹每个控制点的 z 由与运动模拟器同一张地面网格决定
  （`PlannerManager::applyTerrainZReference`），不再用起终点线性插值。
- **网格边界插值**：改为先夹取连续坐标再插值；新增 `contains()`，越界不被当成可行驶地面。
- **地形判据**：`check_terrain` 分 uphill/downhill/crest/flat 检查方向与幅度，
  禁用 `abs(rise)`（用 Codex 反例验证：持续下降数据按 uphill 现在失败）。
- **本地地面估计**：每格低分位数 + 补洞 + 中值平滑，可跟随坡道。
  **但未证实能解开洞口连通性**——用本地地面重算，结论与全局一致。
- **遗留项**：冒烟脚本改进程组清理（全仓库无 `pkill -f`）；新增任务授权话题
  `planning/task_active`，取消后必须重新授权才执行；无 `start_time` 的轨迹在取消后一律拒绝；
  停车判据要求录满观察窗；Mode2/3/spin 不再 `CHECK=none`。
- **受控洞口场景**：高洞（洞顶 0.45 m）通过、低洞（0.20 m）拒绝，判据闭环。
- **RViz**：地形实体网格（4000 三角面按高度着色）+ 实体机体（0.52×0.52×0.25 m），
  点云/占据/包络为可开关调试层。**观感仍待用户验收。**
- **真实场地三处坐标核对**：三处**洞顶都不是阻挡原因**（0.287/0.449/露天），
  阻挡来自坐标点自身压在结构上；开口就在旁边且宽 1.6~4.2 m。

## 第三轮：地形分离与高度跟随

用户验收 RViz 后反馈坡度不明显。排查确认**根因不是 RViz、也不是缺 Gazebo**：
运动模拟器 z 恒定，且上一版绝对高度删点把地面整层删掉（631508 点只留 177762）。

- 新增 `prepare_terrain_map.py`：稳健拟合二次地面曲面（RMS 0.05 m），障碍 = 高于地面 ≥0.08 m；
  障碍云喂 SCAN，地形表面仅 RViz 显示，地面网格供高度查询。
  新方法保留 310659 个障碍点，**多保留的 132897 个正是被旧做法删掉的 z<0.30 m 真实结构**。
- 高度跟随：模拟器 z = 地面 + body_height（由地形推导，不抄轨迹 z）；
  Mode 3/2 的路点 z 由 `make_terrain_route.py` 从同一网格生成；
  Mode 1 目标高度改为目标处地形查询。
- 验证：合成 10/20/30° 坡的上升量与 `tan(角度)×3 m` 完全一致；真实场地路线上升 0.140 m。
- **前一版"x=−6 走廊净空 1.187 m"的结论作废**：那条走廊实际有 3822 个障碍点，
  旧结论是删点造成的假象。
- 未做：动力学（无轮地接触/牵引/打滑）、地形规划、台阶识别；轨迹 z 仍是线性插值；
  RViz 图形交互仍未验收。
