# 调研与规划进展

日期：2026-10-01。当前阶段：**S0–S3 已实施并跑通仿真，等待 Codex 审查；实车接入未开始。**

## 第三轮：地形分离与高度跟随（当前状态）

用户验收 RViz 后反馈坡度不明显。排查确认**根因不是 RViz、也不是缺 Gazebo**：
运动模拟器 z 恒定，且上一版绝对高度删点把地面整层删掉（631508 点只留 177762）。

- 新增 `prepare_terrain_map.py`：稳健拟合二次地面曲面（RMS 0.05 m），障碍 = 高于地面 ≥0.08 m；
  障碍云喂 SCAN，地形表面仅 RViz 显示，地面网格供高度查询。
  新方法保留 310659 个障碍点，**多保留的 132897 个正是被旧做法删掉的 z<0.30 m 真实结构**。
- 高度跟随：模拟器 z = 地面 + body_height（由地形推导，不抄轨迹 z）；
  Mode 3/2 的路点 z 由 `make_terrain_route.py` 从同一网格生成；
  Mode 1 目标高度改为目标处地形查询。
- 验证：合成 10/20/30° 坡的上升量与 `tan(角度)×3 m` 完全一致；真实场地路线上升 0.140 m。
- **前一版"x=−6 走廊净空 1.187 m"的结论作废**：那条走廊实际有 3822 个障碍点，
  旧结论是删点造成的假象。
- 未做：动力学（无轮地接触/牵引/打滑）、地形规划、台阶识别；轨迹 z 仍是线性插值；
  RViz 图形交互仍未验收。

## 第二轮：Codex 审查后的修正

Codex 第一轮审查结论是"方向正确但不能认定已验收"，提出 4 项缺陷并驳回 3 项主张。
本轮全部处理，**尚未复审**：

- **取消后重新运动**（Codex 有日志反证）：FSM 增加 `planning/reset` 处理，取消时清目标与
  轨迹时间基准并回 `WAIT_TARGET`；跟踪器增加取消闩锁拒绝在途旧轨迹。复测：取消后 6 s 内
  605 个命令样本全为 0。
- **过期轨迹被从头执行**：改为明确拒绝（过期/未来时间/取消前），不再重置为 t=0。
- **测试脚本宽泛 pkill**：改用 `setsid` 独立进程组，只杀本次进程组。
- **测试误判通过**：判据抽到 `check_stop.py`（从实际事件计时 + 要求持续静止 + 失败返回非零）；
  记录器不再按场景名分流，改由显式参数驱动并真正等待观察窗。
- **地面删点降级为演示方案**：参数/日志/文档统一标注"绝对高度切图，非地面识别"，
  发布未过滤对照云，并用受控场景量化代价。正式的地面分割**未实现**。
- **碰撞验收补受控场景**：4 张合成地图（封闭房间 + 带缺口隔墙）覆盖"宽于车体通过 /
  窄于车体拒绝 / 中心线不碰但车体边缘会碰时拒绝 / 矮障碍必须仍然拦停"。
  三类拒绝均由 `A-star failed`（膨胀占据图无通路）驱动、可行性失败为 0。
- **RViz** 仍为未验证，措辞改为"无界面闭环已有运行记录；RViz 交互待验收"。

新增脚本：`check_stop.py`、`check_passage.py`、`make_test_maps.py`、`summarize_launch_log.sh`。

## S0–S3 首轮实施结果（已被上节修正取代，保留供追溯）

- **S0**：记录用户给定的 PCD、半径 0.26 m、高 0.25 m、雷达外参、MPPI 限速；解析 PCD
  发现地面高度散布 -0.06..0.22 m。见 [S0 基线](s0_baseline.md)。
- **S0**：把 SCAN-Planner-Ros2 main `103bce4` 的 9 个包纳入本仓库 `src/`，未修改参考仓库。
- **S1**：取消「先对齐轨迹 yaw 才平移」的门槛；新增 `yaw_mode`(hold/align/spin)；
  碰撞包络改为 offset=0 的单圆柱（半径 0.26 + 余量，高度带 [0, 0.25]），
  由于所有查询都走 `getInflateOccupancy`，碰撞代价/安全检查/RViz 显示语义自动一致；
  新增 odom 陈旧、非法轨迹、`planning/reset` 取消等保护；收轨迹时按 `start_time` 对齐执行时间。
- **S2**：`map_pub` 增加地面过滤与 z 归零；`pcl_render_node` 增加可配置雷达外参并使射线原点、
  `sensor_pose`、`world→sensor` TF 使用同一外参；新增 `sentry_sim.launch.py`（`/sentry_sim`
  命名空间）与 RViz 配置，三模式全部保留。闭环为真实速度闭环（速度积分反馈 odom），
  未使用 open_loop_controller。
- **S3**：9 个场景验证全部通过，详见 [S3 结果](../testing/s3_results.md)：
  车头不变横移（dx=0.000、朝向偏离 0.00°）、取消门槛（旋转 90° 同时平移到位）、
  边转边走（自转 179.9° 仍走直线）、三模式全部到达、贴障通过（独立净空 0.345 m ≥ 0.26）、
  阻挡目标不动、取消后 0.670 s 停车、里程计断流后 2599 个采样全为 0。
- **明确未验证**：RViz 图形交互（本环境无法创建 OpenGL 上下文）、实车、爬坡、加速度上限合理性。
- 环境适配：本机 MVS SDK 的 libusb 会破坏 PCL 运行期符号解析，`run_sentry_sim.sh` 中剔除；
  这是环境修复，不是源码改动。

本轮修改的代码在 `src/`，清单见 [实施报告](implementation_report.md)。RM 与两个 SCAN
参考仓库均未修改。

已知仍需审查者关注的点：

2. **RViz 图形交互未验证**：需要用户在带显示的机器上确认地图/包络/轨迹显示与
   点击 2D Goal Pose 后运动、重设目标、停止操作。
3. `collision_block` 的拒绝来自动力学可行性检查而非碰撞代价否决；受控场景
   （`gap_narrow`/`gap_edge`/`low_obstacle`）已用 A*-驱动的拒绝覆盖碰撞逻辑本身。
4. 启动瞬间 FSM 会重试数次 `The robot is inside an obstacle`（疑似越界返回 -1 被当作占据）。
5. `grid_map/occupancy_inflate` 频率偏低（仅影响 RViz 显示刷新）。
