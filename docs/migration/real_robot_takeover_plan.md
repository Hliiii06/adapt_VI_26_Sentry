# 实车接管方案（最小改动，PROPOSED，待审查与批准）

日期：2026-10-09。状态：**PROPOSED，未实施**。本轮只授权只读影子；
**受控驱车必须经 Codex 审查 + 用户明确同意**。现场流程见[在线影子运行手册](onsite_shadow_runbook.md)。

一句话：**先让影子把"输入对齐/规划合理"证明清楚；接管只在"单一速度源 + 默认撤权 + 可控急停"三件事
同时成立时才做，首轮只平地低速。**

## 一、单一速度来源（互斥，不靠 mux 假装仲裁）

事实（**现场实测，用户回传 2026-10-09**）：底盘入口话题为 `/cmd_vel`，
当前发布者是导航栈 **`controller_server`**，消息类型 `geometry_msgs/msg/Twist`（订阅者同为 `Twist`）。
（静态历史证据：`hnurm_uart` 的 `twist_topic` 被现场 YAML 覆盖为 `/cmd_vel`；
另有 `behavior_server`、决策 `PubRobotStatus`→`/cmd_vel_remap` 等潜在分支。）
**"两个规划器都在跑 + 一个 mux"不算互斥**。

由于候选速度已经是 `Twist`，接管期的命令闸门**直接发布 `geometry_msgs/msg/Twist` 到 `/cmd_vel` 即可**，
不需要类型转换；但必须确认 `behavior_server` 是否也在发同一话题（若会，切换前必须先停它的发布）。

接管期要求：

1. 同一时刻**只有一个进程**有权发布底盘速度话题；
2. 切换顺序固定：**先撤权停车 → 确认速度为零 → 停旧源 → 再授权新源**；
3. SCAN 侧的最终速度只经过一个**命令闸门**（本仓库新增，非 SCAN 核心改动），
   闸门是唯一允许发布底盘话题的 SCAN 节点；
4. 旧 Nav2 不是"关掉就算"：需要停 controller/behavior 的发布（生命周期 deactivate 或整组停），
   并确认 `/cmd_vel` 的发布者名单只剩闸门；
5. 每次切换后都用 `ros2 topic info -v <底盘话题>` 核对发布者名单，作为操作记录的一部分。

优先的接入方式（**不改 RM 源码**）：

```text
SCAN 跟踪器 ──/sentry_scan/cmd_vel_candidate──> 命令闸门 ──> <底盘话题>
                                                 ▲
                            健康/心跳/授权/新鲜度/限幅/看门狗
```

- 影子阶段已有**只读版输入闸门**（`input_gate:=true` 的 `input_pause_gate`，只暂停转发、不发布速度），
  接管期的命令闸门复用同一位置与同一套健康/心跳/授权判定，只是把输出接到底盘话题；
- 闸门默认**不发布**；只有显式授权（`planning/task_active` 的 `task_id` 更高 + 操作者使能）且
  健康、地图心跳新鲜时才透传；
- 可选把 `hnurm_uart` 的 `twist_topic` 参数指向闸门输出（如 `/sentry_scan/cmd_vel_gated`），
  这是**launch 参数**，不是源码修改；
- 若现场实测 UART 的订阅类型/QoS 与我们的发布不兼容（例如需要 `TwistStamped`），
  先在**本仓库**做转换节点，不动 RM。

## 二、默认禁止输出 / 显式使能 / 取消 / 超时停车 / 退出恢复

| 机制 | 实现要点 | 判据 |
|---|---|---|
| 默认禁止输出 | 闸门启动即撤权状态，不发布任何底盘消息；影子入口没有"下发"开关 | 启动后底盘话题发布者里没有闸门 |
| 显式使能 | 需要：① 影子健康（`health_ok`）；② 地图心跳新鲜；③ 规划端新任务授权（`task_id` 更大）；④ 操作者显式使能（命令行/专用话题） | 四个条件缺一即零 |
| 取消 | `planning/reset` → 本地立即锁止 → 清轨迹 → 闸门归零 | 取消后限时归零、旧轨迹不复活（已由影子矩阵验证逻辑） |
| 超时停车 | 候选速度超时（`candidate_timeout`）、输入失效、地图停更 → 闸门归零并撤权 | 各类失效场景均已按"先动后停"验证 |
| 退出恢复 | Ctrl-C 闸门 → 底盘速度源回到原 Nav2（重新 activate/启动原 launch）；SCAN 侧状态全部丢弃 | 原导航可再次接管并正常行驶 |
| 硬失败 | 闸门进程死亡：MCU/固件侧 watch dog 必须独立把速度归零（现场确认时限） | 拔掉闸门/杀进程后车辆在确认时限内停住 |

**不借用**仿真的 `cmd_timeout`（那是运动模拟器的功能），也不把闸门自身当作最后一道安全。

## 三、现场急停与退回原导航

1. **急停**：用户确认（2026-10-09）现场**存在可立即停车的急停**；首轮测试安排**专人**守在急停旁；
2. 测试前演练一次急停（不接 SCAN，仅确认它能停住车辆）；
   **仍需确认**：MCU/固件侧"速度命令超时自动归零"的时限——这是闸门进程死亡时的最后一道保护；
3. 退回原导航：停闸门 → 恢复原 Nav2 启动（或重新 activate）→ 确认 `/cmd_vel` 发布者恢复为原节点 →
   原地小幅验证一次（用户操作）；
4. 记录：切换前后发布者名单、时间、执行人。

## 四、首轮低速测试步骤（全部需用户确认后执行）

前提：在线影子已通过 §8 的 7 个问题的检查（输入对齐、地图更新、路径不穿墙穿地、失效行为、
影子未接控制出口）。

| 步骤 | 内容 | 建议上限（**待用户确认**） |
|---|---|---|
| T0 | 车辆支起/空旷平地，接闸门但**不使能**，确认无输出 | 输出恒 0 |

包络已确认（半径 0.26 m、高 0.15 m 的圆柱），接管期使用 `robot_radius=0.26`、`robot_height=0.15`、
`safety_margin=0`；**不得**为了通过而改小。
| T1 | 使能后直行 1 m 后停止 | `vx ≤ 0.2 m/s`、`|ax| ≤ 0.3 m/s²` |
| T2 | 横移 1 m 后停止（车头不动） | `|vy| ≤ 0.2 m/s` |
| T3 | 直行中取消任务 | 停止时限 ≤ 0.5 s（待确认） |
| T4 | 模拟输入失效（停影子输入） | 停止时限 ≤ 0.5 s，且不自动恢复 |
| T5 | 退出闸门，恢复原 Nav2 | 原导航可正常接管 |

- `wz`（旋转）**首轮不接管**：MCU/电控保留朝向与小陀螺；闸门只透传 `vx/vy`；
- 上述数值是**待确认的占位值**，不是标定结果；用户确认前不得实测；
- 任何一步出现异常（方向反、抖动、超调、未停住）：立即急停并回传日志与现象。

## 五、RM 是否需要修改

**默认答案：不需要改 RM 源码。** 需要的都是运行期动作或本仓库侧新增：

| 需要 | 是否改 RM | 说明 |
|---|---|---|
| 读取 `/Odometry_transformed`、`/LIVO2/imu_propagate`、`/cloud_registered`、TF | 否 | 只订阅 |
| 把底盘速度源从 Nav2 切到闸门 | 否 | 运行期使能/停 Nav2；必要时用 UART 的 `twist_topic` 参数 |
| UART 订阅类型/QoS 适配 | 否 | 若需要，在本仓库加转换节点 |
| 固件 watchdog 超时**时限** | 否 | 急停已确认存在且可立即停车；但"速度命令停发后多久归零"仍 UNKNOWN，需现场确认（若固件缺失须单独评估，可能要电控改，另申请） |
| 参考中心/杆臂/IMU 原点与外参核对 | 否 | 通过适配参数表达，不改 RM |

**只有在**现场实测证明"必须动 RM 源码"时（例如 UART 只接受某种消息且无法用参数/外挂转换满足），
才单独列出**最小改动清单**（文件、函数、diff、回滚方式）并**再次申请许可**；本轮不预先修改。

## 六、接管前的门槛清单（缺一不做）

1. 影子运行手册 §8 的 7 项全部有实际数据结论；
2. 现场确认：`world`↔规划系关系、IMU 角速度/杆臂、真实云 stamp 时钟尺度、真实尺寸与最低点；
3. 闸门实现并经过：默认使能禁止、取消、超时、失效、恢复、限幅、NaN、看门狗；
4. `ros2 topic info -v` 证明单一速度源；
5. 急停演练通过，且有现场安全员；
6. 用户书面/口头明确同意首轮低速测试与上述速度/加速度上限；
7. Codex 审查通过。
