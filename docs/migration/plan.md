### 保留三种输入

- Mode 1：RViz “2D Goal Pose”指定目标；保留原高度语义（目标处地面 + `body_height`）。
- Mode 2：参数配置多个航点（机体参考中心 XYZ）；不得在重写 launch 时遗漏。
- Mode 3：输入带高度的参考路线；地面 z 与 `body_height` 只相加一次。

Mode 1 不是地图全局通路搜索，不要求复杂迷宫可达性等同 Nav2。Mode 2/3 不能只验证启动成功。

### 碰撞与包络原则

运动方向不等于车头方向，不能无条件以轨迹切线代表车体 yaw。当前实现用与朝向无关的
**单圆柱包络**（半径 = `double_cylinder_radius` + `safety_margin`，高度带由 z 膨胀决定），
碰撞代价、FSM 安全检查与 RViz 显示共用 `getInflateOccupancy` 语义；
参数语义与索引方向见[SCAN 架构](../architecture/scan_planner.md)。精细朝向预测模型仍是 PROPOSED。

## 执行与停止规则（计划级门槛）

细节要求（输入健康门控、轨迹校验、取消/失效锁止、单一速度源、watchdog、限速与急停）
以[交接 B](real_robot_handoff.md)的 B2 与测试矩阵为**唯一来源**，本页只保留门槛：

1. 最终速度输出必须有**单一授权来源**；影子阶段默认不授权，MCU 保留朝向/小陀螺职责。
2. 输入失效、任务取消、轨迹非法或越界时，输出必须停止且旧轨迹不得重新激活。
3. 保护进程自身死亡不能靠自己发零兜底；实车门槛包含 MCU 失联停车与独立急停验证。

## 切换与回退

影子模式只读旧链，默认不授予控制权。实车模式切换先撤权、停车、隔离旧 controller/behavior
等所有速度源，再授予 SCAN；不能在两套 launch 同时直发 `/cmd_vel` 时用额外 mux 假装仲裁。
回退时撤销 SCAN 授权并确认停车，停止新执行链，恢复原 launch/参数与唯一旧速度源；
不需要还原 LIO/TF/串口源码。当前未更改旧链，不执行切换。

## 审查边界

Codex 按“实现是否满足交接要求”审查，不把静态审查等同实车安全批准；
影子验收通过也不等于允许驱车。历史设计与已完成阶段见[进展](progress.md)与
[进展历史](../archive/progress_history.md)。
