# S3 场景验证结果

日期：2026-10-01。环境：ROS 2 Humble、本仓库隔离构建（`--symlink-install`，9 个包）、
地图 `~/pcd_map/rmuc2026_field.pcd`、机器人半径 0.26 m / 高 0.25 m、
限速 `vx ±1.0 / |vy| 1.0 / |wz| 1.5`（取自 RM 的 MPPI Omni 配置）。

复现：`scripts/scenario.sh <场景>`；原始报告在 [evidence/](evidence/)；
净空由 `scripts/check_clearance.py` 独立计算（不调用 SCAN 的碰撞函数）。

## 逐项说明

### 三模式全部可用

Mode 1（RViz 目标）、Mode 2（参数航点）、Mode 3（参考路线）都能驱动机器人完整走完
6.2 m 走廊并停在目标附近（0.001–0.005 m）。Mode 2 依次到达 3 个航点，日志可见
`Planning to waypoint 1/3 → 2/3 → 3/3`。

### 车头不变横移（`mode1_lateral`）

`dx = +0.000 m`、`dy = +6.245 m`、朝向偏离 **0.00°**：机器人纯 +Y 横移，机身始终朝 +X。
`|vy|` 峰值正好 1.000，即 MPPI 的 `vy_max`。这正是上游做不到的场景——上游会先要求
对齐轨迹切线朝向。

### 取消强制对齐门槛（`mode1_align`）

同一个目标，`yaw_mode=align`：机器人一边把车头转向轨迹切线（最终 yaw=1.5708 rad，
即 90°），一边**继续平移**并到达目标（0.004 m）。`|wz|` 峰值 1.500 说明角速度已到限幅，
平移却没有被冻结。上游在 `|yaw_error| > 0.8 rad` 时只会原地转向并冻结 `exec_time`，
本场景在上游逻辑下会永远停在起点附近。

### 边转边走（`spin`）

`yaw_mode=spin`、`spin_rate=0.5`：机器人自转累计超过 179.9°，位移仍然是纯 +Y
（`dx = +0.000`）并准确到达目标。这说明**机体旋转没有污染世界系运动方向**，
速度的 world↔body 变换与实际姿态一致。旋转仅用于测试跟踪与包络，不代表电控小陀螺行为。

### 独立净空检查（不依赖 SCAN 自身判断）

对每条轨迹的每个位姿，在原始 PCD 的高度带 `[0.30, 0.55]` m 内查找最近点：

| 场景 | 最小水平净空 | 要求 | 结论 |
|---|---|---|---|
| `mode1_lateral` / `mode2_waypoints` / `mode3_path` / `spin` | 1.187 m | ≥ 0.260 m | 通过 |
| `tight_pass` | **0.345 m**（出现在终点） | ≥ 0.260 m | 通过 |
| `collision_block` | 1.187 m（未移动） | ≥ 0.260 m | 通过 |

`tight_pass` 的目标本身只有 0.344 m 净空，机器人停在离障碍 0.345 m 处，
说明包络在贴障场景下确实生效且未被侵入。

### 拒绝执行（`collision_block`）

目标 `(-6.98, 0.58)` 落在障碍点云上。机器人**全程未移动**（0 位移、0 命令），
不会驶入障碍。

**诚实说明**：日志显示这次的拒绝来自 `bspline_opt` 的动力学可行性检查
（`acceleration 1.537 > 1.500`），而不是碰撞代价单独否决。安全结果是正确的
（不动、不撞），但不能据此宣称"碰撞检查单独拦住了这个目标"。

### 取消（`cancel`）

机器人在 t=4 s（还在走廊中段 y=5.642）收到 `planning/reset=true`，**0.670 s 内**速度
降到 0 并保持。取消后不会重新激活旧轨迹。

### 里程计断流（`odom_loss`）

Mode 2 行驶途中杀掉 `go2_kinematic_sim`（`body_pose` 停止发布）。`cmd_vel` 记录：

```
cmd_vel 样本数: 3407，其中非零: 773
最后一次非零命令: t=8.03s
其后样本数: 2599，其中仍非零: 0
```

断流后 2599 个采样全部为 0，符合 `odom_timeout = 0.5 s` 的预期。

原始数据：[evidence/odom_loss_cmdvel.csv](evidence/odom_loss_cmdvel.csv)。

## 未验证项（不得当成已通过）

| 项 | 原因 |
|---|---|
| **RViz 图形交互** | 本环境无法创建 OpenGL/GLX 上下文（`Failed to create an OpenGL context`），所有验证都在 `start_rviz:=false` 下完成。RViz 配置可解析（12 个显示项、Fixed Frame `world`）、其订阅的话题均已确认存在，但**"用户能用 2D Goal Pose 点目标"这一交互未经验证**。 |
| 真实爬坡 / 台阶 / 轮地接触 | 首版平地固定 z；带高度路线只验证高度偏置规则，不验证动力学 |
| 电控小陀螺、UART 协议、固件 watchdog | 本阶段不接实车 |
| 实车跟踪误差、停车时间、速度/加速度上限 | 需用户与硬件条件确认阈值 |
| 加速度上限的合理性 | 仿真用 `max_acc_xy=1.0`、`max_acc_yaw=2.0` 是示例值；RM 的 MPPI 加速度上限为 UNKNOWN |
| 与原 PCD 等价的窄通道（0.26–0.5 m 净空）规划行为 | `tight_pass` 覆盖到 0.345 m，但没有构造"车体放不下"的窄门用例 |

## 观察到的上游行为（非本次引入的缺陷）

- **启动瞬间的 `The robot is inside an obstacle`**：每次启动会打印 2–4 次，随后 FSM 自行
  恢复正常。原因疑似 `getInflateOccupancy` 在滑窗地图尚未覆盖机体位置时返回 `-1`（越界），
  而调用方按"非零即占据"处理。这是保守语义（越界视为不可通行），不是本适配引入的问题；
  但它会让每次启动多花几百毫秒重试，值得在后续评审中确认。
- **到达目标后仍持续重规划**：目标到达后 FSM 会继续尝试重规划，失败 1000 次后进入
  `EMERGENCY_STOP` 并回到 `WAIT_TARGET`。机器人在此期间保持静止（跟踪器的到位判定
  会发零速），最终状态是安全的。
