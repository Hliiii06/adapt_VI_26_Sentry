# Codex 第二轮复审修正

日期：2026-10-01。本轮只收尾复审指出的 4 项实现问题并补针对性反例测试，
未扩展功能，未调整地图阈值来让测试通过。

## 1. 高度修正必须在**优化之后**（高优先级）

**问题**：`applyTerrainZReference()` 原本只作用于**优化前的初始采样点**；
优化会改变 XY，而优化器把 z 梯度置零，因此绕障后的轨迹 z 仍沿用优化前的位置。
交付说明里"绕障后 XY 变了 z 跟着变"与代码不符。

**修正**（`planner_manager.cpp`）：
- 新增 `applyTerrainZToControlPoints()`，在**优化成功之后**按新的 XY 重新查询地形赋 z；
  **时间重分配（refine）之后**再执行一次（refine 同样会改变控制点位置）。
- 两处任一发现控制点越出地面网格即拒绝整条轨迹。

**验收**（`scripts/scenario.sh terrain_lateral`）：
横向 12° 坡面（x=0 处地面 0.000 m，x=+0.80 处 +0.170 m）+ 中央障碍逼迫横向绕行。

| 指标 | 实测 |
|---|---|
| 横向绕行跨度 | **0.981 m** |
| 高度跨度 | **0.209 m** |
| 横向高位侧平均 z / 低位侧平均 z | 0.322 / 0.125（差 **0.197 m**） |
| **规划高度 vs 实际执行高度** | 212 个采样点，最大偏差 **0.0096 m**（容差 0.060） |
| 按**实际执行高度**重放障碍检查 | **0 / 6701 帧碰撞** |
| 反例对照：起终点线性插值高度 | 与实际相差最大 **0.2085 m** |

即：规划器检查的高度与实际执行的高度一致到 1 cm 以内，且高度确实随横向地形变化。

**本轮未能证明的部分（如实说明）**：线性高度假设在该路径上**没有**造成碰撞
（0 帧 vs 0 帧）。所以本场景证明的是"高度跟随了横向地形、且规划与执行一致"，
**不能**用来声称"修复前的线性插值会导致碰撞"。要制造碰撞差异需要更陡的横向坡
或更低的洞顶，本轮没有构造。

## 2. 实体机体显示与碰撞包络几何一致（高优先级）

**问题**：包络是半径 0.26 m 的圆柱，显示却是 0.52×0.52 m 的**方块**；
方块角点到中心 √(0.26²+0.26²)=**0.368 m**，四角露在包络之外，
会出现"画面里车角碰墙、规划器却认为安全"。参数同源不等于几何一致。

**修正**（`go2_kinematic_sim.cpp`）：显示改为 **CYLINDER**，半径 = `robot_radius`（0.26 m），
高 = 2×body_height（0.25 m），与碰撞包络完全同形。

## 3. 取消时立即本地锁止，旧授权不得重新放行（高优先级）

**问题**：跟踪器的 `resetCallback()` 只清轨迹，没有把 `task_active_` 置为禁止。
它要等规划端稍后发布撤权；在此间隙，规划端若仍在计算旧任务，
会发布一条 `start_time` 晚于取消时刻的轨迹并被接受——竞态窗口仍在。

**修正**：
- `resetCallback()` 现在**立即**调用 `lockOutLocally()`，本地锁止并把"已撤销到的任务编号"
  推进到当前最大编号，不等规划端。
- 授权消息由 `std_msgs/Bool` 换成新的 `scan_planner_msgs/TaskAuthorization`
  （`header` + `active` + `task_id`）。规划端每接受一个新任务 `task_id` 自增；
  执行端只接受 `task_id > revoked_up_to_` 的授权。
  **在取消之前发布、延迟到达的旧授权编号不会更大，因此不会解锁。**

**验收**（`scripts/scenario.sh cancel_race`）：发送目标后 0.15 s（规划进行中）取消，
然后注入一条延迟到达的旧授权（`task_id=1`）和一条 `start_time` 晚于取消时刻的轨迹。

| 指标 | 实测 |
|---|---|
| 归零延迟 | **0.000 s**（时限 0.20 s） |
| 取消后观察窗 | 605 个样本，非零 **0** 个 |
| 观测覆盖 | 9.63 s（要求 >= 6.00 s 完整时长），最大间隔 0.0113 s |
| 注入的旧授权 | 日志：`Ignoring stale task authorization task_id=1 (revoked up to 3)` |
| 注入的新时间戳轨迹 | 未产生运动（授权门控保持锁止） |

> 注：首次运行时注入的授权用了 volatile QoS，与执行端的 transient_local 订阅不兼容，
> 消息**根本没被收到**——测试会"通过"但什么都没验证。已改正 QoS 并确认日志出现上述拒绝行。

## 4. 越界不得继续移动（中优先级）

**问题**：模拟器越界后只保留旧 z 继续走；规划端对越界点回退到线性高度继续处理。
两者都等于把未知区域当成了可行驶地面。

**修正**：
- **规划端**：初始点集或优化后控制点越出地面网格 → **拒绝整条轨迹**并计数失败。
- **模拟器**：下一步位置越界时**停在边界**（位置钉在最后一个已知点、速度清零）并告警，
  不再保持高度继续前进。

**验收**（`scripts/scenario.sh goal_out_of_grid`）：在小地面网格（x∈[−1,1]）上发送
网格外目标 (5.0, 5.0)。

| 指标 | 实测 |
|---|---|
| 日志 | `Rejecting trajectory: 8 of 24 initial points are outside the known ground grid` |
| 机器人位置 | 停在 (0.0, −2.0)，未移动 |
| 命令 | 3134 个样本覆盖 31.33 s，峰值全为 **0.000**，最大间隔 0.0121 s |

新增 `scripts/check_no_motion.py`：`check_stop.py` 要求"事件前有明显非零命令"
（用于证明先动后停），对"本就不该动"的场景会判成"场景无效"，
因此单独写了全程零命令 + 覆盖完整时长 + 中间不缺样的判据。
场景同时要求日志里出现越界拒绝，以区分"拒绝规划"与"根本没收到目标"。

## 5. 停车判据改为完整时长（复审附带指出）

`check_stop.py` 原来接受 `--observe` 的 90%，报告却写成完整观察。
现改为**按完整时长检查**，并新增**中间缺样检查**（最大采样间隔须 <= max(0.25s, 5×中位间隔)）。
实测：cancel 覆盖 9.01 s / 要求 6.0 s；cancel_race 覆盖 9.63 s / 要求 6.0 s，均无缺样。
